# Архитектура главного сайта

## Роль сайта

`soboleva_vizitka` — будущий основной сайт визового проекта. Он будет содержать главную страницу, услуги, статьи, юридические страницы и позже клиентские сценарии (форма, CRM, бот).

## Стек сегодня

- React + TypeScript;
- Vite для локального запуска и production-сборки;
- Tailwind-классы в компонентах;
- Lucide для иконок;
- статический сайт: без базы данных и своего backend.

## Ближайшая целевая структура

```text
soboleva_vizitka/
├── components/        визуальные блоки React
├── config/            ссылки, контакты, настройки CTA
├── content/           подключённые Markdown-статьи
├── public/            локальные изображения и иллюстрации
├── docs/              правила дизайна и редакционные шаблоны
└── App.tsx            временная точка сборки страниц
```

## Правила

1. Новые ссылки добавляются в `config/links.ts` и отмечаются в общем `CTA_LINKS.md`.
2. Новые статьи сначала создаются по Markdown-шаблону, затем получают визуальную страницу.
3. Картинки постепенно забираем с внешних адресов в `public/media/`; случайные изображения нельзя выпускать в продакшен.
4. Ключи, токены бота, пароли сервера и данные CRM не хранятся в React-коде.
5. Сначала локальная проверка, затем сервер.
6. Все страницы публикуются по чистым адресам без `#`. Подробное правило маршрутов — в [`docs/ROUTING.md`](docs/ROUTING.md).

## Что ещё не сделано

- постепенное разделение Safe Case на React-компоненты с обязательным сохранением полного паритета с `content/safe-case/source.html`.
