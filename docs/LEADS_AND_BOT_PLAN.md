# Заявки, Prodamus XL и Telegram-бот

## Решение на сейчас

Выбран путь 1: как можно быстрее подключить существующий квиз Prodamus XL
к визовым сайтам и проверить, что он стабильно собирает заявки в CRM Prodamus.

Первое подключение — финальный блок `#zayavka` в статье Safe Case. Текст блока:

> Чтобы оставить заявку, пройдите короткий опрос

Квиз остаётся источником заявки в Prodamus. Ссылка «Написать напрямую в
Telegram» остаётся резервным способом связи, если человеку удобнее написать.

## Что проверяем в ближайшем будущем

1. Квиз виден и открывается на маршруте Safe Case на телефоне и на десктопе.
2. Тестовая заявка появляется в нужной CRM Prodamus с ответами и источником.
3. Сценарий Prodamus после завершения формы отправляет штатное уведомление.
4. Фиксируем, какие поля и переменные реально отдаёт XL: идентификатор
   виджета, источник, ответы, имя, телефон, почта и UTM-метки.
5. Только после этого решаем, где ещё ставить виджет и нужен ли свой backend.

На этом этапе не создаём серверный API, не переносим клиентские данные из
Prodamus и не отключаем существующие сценарии.

## Целевой процесс для команды

У команды одна общая база заявок. В Telegram работает один бот, который знает
роли сотрудников по их Telegram user ID:

- Александр — владелец и администратор;
- Ирина — эксперт по визам и администратор;
- Виолета — обработчик заявок и администратор.

Новая заявка приходит всем трём. Каждое изменение записывается в общей базе,
поэтому Ирина и Александр сразу видят, что Виолета взяла клиента в работу, а
также комментарии и историю переходов.

### Карточка новой заявки в боте

Уведомление должно содержать только необходимые рабочие данные:

- имя и фамилию;
- телефон и почту, если посетитель их указал;
- основную метку пользователя;
- сайт и конкретный квиз, откуда пришла заявка;
- UTM-метки и рекламный источник, если они были переданы;
- все ответы квиза в понятном виде;
- текущий статус и ссылку/идентификатор карточки.

Ник и Telegram ID клиента нельзя получить по одному номеру телефона или почте
с сайта. Они появляются только когда человек сам запускает бота, пишет ему или
явно передаёт эти данные через Telegram. Поле `telegram_username` должно быть
необязательным: у пользователя может не быть ника.

### Статусы и действия

Первый набор статусов фиксирован:

1. Новое.
2. Обработано.
3. Заключаем договор.
4. Принимаем деньги.

В карточке нужны кнопки смены статуса и действие «Добавить комментарий».
Бот записывает автора, время и прежний/новый статус. Это важно, чтобы не
терять контекст, когда с одним клиентом работает несколько человек.

### Первое меню бота

- новые заявки;
- заявки за последние 7 дней;
- поиск по имени, телефону или почте;
- воронка за 7 дней: количество и конверсия между четырьмя статусами;
- мои действия и комментарии.

Позднее можно добавить фильтры по сайту, рекламной метке, ответственному,
причине отказа и периоду. Массовые маркетинговые рассылки не включаем, пока не
зафиксированы согласие клиента, канал связи и правила коммуникации.

## Путь к независимости без резкого переезда

После проверки пути 1 следующий этап — путь 2:

```text
свой красивый виджет на Visa
  → наш backend
  → Prodamus XL CRM и сценарии
  → уведомление Telegram-бота
```

Ключ API Prodamus и токен Telegram-бота хранятся только на сервере, никогда
не в React-коде, Git или сообщениях. Веб-запрос из сценария XL нужен для
обратного направления `Prodamus XL → наш backend`; отправка данных из своего
виджета в XL идёт через API с серверной стороны.

Путь 3 — полная независимость — строится постепенно: сначала собственная база
контактов и событий, затем бот и минимальная воронка. Не нужно сразу создавать
большую CRM. Минимальные сущности:

```text
contacts        контактные данные и согласия
lead_events     ответы, источники и история действий
lead_statuses   текущий статус и его изменения
lead_comments   комментарии сотрудников
bot_users       роли сотрудников и Telegram user ID
```

База с персональными данными, журнал событий и токены должны находиться на
production-ru. NL используется только для разработки и контроля. Подключение
backend, базы, маршрута домена или бота — отдельное серверное изменение и
требует явного подтверждения владельца.

## Критерий следующего решения

После серии реальных тестовых и первых боевых заявок оцениваем:

- достаточно ли данных в карточке Prodamus;
- насколько удобно команде получать и обрабатывать заявки;
- нужны ли свои поля, статусы или комментарии;
- насколько дизайн XL-квиза соответствует сайту;
- пора ли включать backend как переход к своей системе.
